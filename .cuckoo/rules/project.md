# Cuckoo Code 工作规则（始终适用）

> 技术分层规则见同目录其它 `.md`（按 `paths` 生效）；架构 / 构建 / 任务纪律见项目介绍。
> 本文件是**工作纪律速查**，约束"怎么干活"，不重复项目介绍的技术约定。

## 开工前

- **先读 `.agents/handoff.md`**：会话接续状态、上次进展、未完成事项；以本地源码为准。
- 有疑问先问，禁止猜测；指令模糊立即暂停澄清。

## 改代码前：方案自审

- 复杂改动（多文件 / 跨模块 / 架构）：拆子任务 + 扫标识符**全部调用链**，评估对外全部副作用。
- 简单改动：至少扫直接调用点，评估直接副作用。
- 一步一验证；禁止临时补丁、局部遗漏、上下文漂移。**Bug 从架构根因入手，禁止盲目改。**

## 改代码时：精准

- 最小影响面、单一目标；拒绝巨型单文件；圈复杂度 < 9。
- 依赖方向铁律 + D12 工具契约 + **生成物禁手改**（`*.generated.ts`、`src/tools/api.d.ts`、`src/ui/shell.html`）——详见项目介绍。
- 改需求文档后跑 `npm run docs:index`（INDEX 自动更新）。

## 改代码后：验证（硬性）

- `npm run typecheck` + `npm test` + `npm run lint` + `npm run compile` **全绿**。
- **改了运行时行为（IPC / hook / 工具 / UI）→ 必须真机 `npm start` 验证。**
- 测试：只写真实集成测试，不深 mock；优先覆盖失败路径。

## 交付自检

- 功能闭环：输入→处理→数据流转→输出，无漏分支、无未消费数据。
- 缺陷防御：边界 / 空值 / 异常捕获；无状态污染、无破坏性改动；依赖配置同步更新。
- 事实结论附**证据信心评分（1-10）**，<7 加风险预警。
- 做不了就明说，不许默默跳过；收尾交付报告（做了什么 / 没做什么 / 验证结果 / 后续建议）。

## 提交纪律

- 工作区常混有多条功能线 → 提交前**分离无关改动**，别一把梭。
- 生成物由 `npm run compile` 产出，不手改。

## 环境

- 外网代理：`http://127.0.0.1:51081`
- 任务结束 / 异常退出：关闭本次启动的服务进程（Electron、MCP 等）释放内存；如需保留测试须显式告知。
