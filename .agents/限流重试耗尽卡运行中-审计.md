## 3. 缺陷与风险取证清单

### 子代理提出问题的独立复核结果

#### 🟢 [误报] 「拟人化延迟 6~16s 与 onAiState 6s 静默的竞态」
- **子代理论点**：sendTick 活跃期不刷新 lastActivityAt，6s 静默会误杀
- **独立取证**：`harness.html:3294-3300` —— `if (sendTickTimer) { if (Date.now() - sendStartAt <= SEND_TICK_MAX_MS) { lastActivityAt = Date.now(); return; } ... }`
- **结论**：**第 3296 行显式续命并 return**，早于第 3303 行的静默判据。子代理未读到该行（其自述遭遇行号漂移）。**误报，无需修复。**
- **信心评分**：10/10

#### 🟢 [误报] 「onMessageDelivered 置忙未续命，看门狗可能误杀」
- **子代理论点**：`harness-bridge.ts:179 setAiGenerating(true)` 不在 markAiActivity 六处内
- **独立取证**：属实——该处确实未调 markAiActivity
- **主代理处置**：**已修复**。虽 120s 窗口足够覆盖 6~16s 拟人化延迟，但「投递到首帧」之间理论上可含模型排队，加一行零成本且语义正确：
  ```js
  onMessageDelivered((info: any) => {
    if (!info) return;
    markAiActivity();   // 新增
    setAiGenerating(true);
  ```
- **信心评分**：9/10（防御性加固，非确证缺陷）

#### 🟡 [真实但低危，接受不修] 「看门狗 120s 对 reasoning 模型长静默的误判」
- **定位**：`src/bridge/harness-bridge.ts:84, 99-101`
- **事实证据**：`AI_GENERATING_STALE_MS = 120000`；markAiActivity 挂在 onStream / onInterceptedResponse / onToolCall / onTaskIdle / onAiError / onUserStop / onMessageDelivered 七处。若 AI 网页真在深度推理且连续 >120s 无任何 token 输出，看门狗会判定陈旧并复位。
- **危害评估**：DeepSeek reasoning 模型在出首个 token 前通常有 thinking 流式输出（会触发 markAiActivity），>120s 完全静默极罕见。即便误判，后果是 harness 收尾到「就绪」——而 AI 页面真实恢复输出时 `onStream` 会重新 `setAiGenerating(true)`，界面自动回到「生成中…」，**可自愈**。
- **决策**：维持 120s。若真实遇到再上调阈值或改为「按模型能力动态判定」。
- **信心评分**：7/10（风险存在但影响可自愈，非阻断）

#### 🟢 [可选优化，不做] 「delayMs 负数通过 Number.isFinite 守卫」
- **取证**：`harness.html:3258` 实际代码为 `if (!Number.isFinite(d) || d <= 0) d = 120000;`
- **结论**：**已含 `d <= 0` 守卫**，负数/0 均回落到 120000。子代理该条为误读。**无需修复。**
- **信心评分**：10/10

#### 🟢 [建议，不做] 「harness-retry-state 抽共享常量」
- **评估**：目前仅 2 处引用（`retry.ts:89` 发送、`ipc/harness.ts:453` 接收），且 bridge 不能 import app 层。抽常量需要新建共享层，收益不抵成本。
- **决策**：保持字符串字面量，两侧注释已写明配对关系。
