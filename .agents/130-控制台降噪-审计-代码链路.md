## 2. 改动链路与闭环核验

### 2.1 核心改动摘要

生产环境下，在 AI 页面 preload（隔离世界）最早期把全局 `console.log/info/debug` 替换为 noop，保留 `warn/error`；开发启动或 `CUCKOO_DEBUG=1/true` 时不安装过滤器；页面主世界 console 不触碰。

数据流向：`out/src/bridge/entry.js`（preload 入口，`src/app/entry.ts:200` 挂载）→ 首个静态 import `console-filter-install.js` → 调用 `installConsoleFilter()` → 读取 `process.env.CUCKOO_DEBUG` / `process.defaultApp` 判定 → 非调试态替换 `console.log/info/debug`。

#### 2.3.3 生产/开发判定在打包版 preload 中的真实性（对应任务项 3）

**官方文档取证**（https://www.electronjs.org/docs/latest/api/process ）：

> `process.defaultApp` *Readonly* — A `boolean`. When the app is started by being passed as parameter to the default Electron executable, this property is `true` **in the main process**, otherwise it is `undefined`.

文档表述明确限定主进程；沙箱 renderer 的 `process` 子集清单亦不含 `defaultApp`。

**本机探针实证**（Electron 44.4.3，`sandbox:false` + `contextIsolation:true`，与 `src/app/entry.ts:201-203` 一致；探针位于 `.agents/tmp-build-a/probe/`，结果 `.agents/tmp-build-a/probe-result.json`）：

| 取值 | 主进程 | preload 渲染进程 |
|---|---|---|
| `process.defaultApp` | `"true"`（boolean） | `type: undefined`，`own: false`（非自有属性） |
| `process.type` | `browser` | `renderer` |
| `process.env.CUCKOO_DEBUG` | — | 设为 `1` 时可透传到 preload（`envDebug: "1"`） |

- 结论 A（生产判定）：打包版 renderer 中 `defaultApp` 同样为 `undefined`，`defaultApp === true` 为 false → 过滤器安装，**生产静默方向正确，无误开风险**。
- 结论 B（开发判定，见 F1）：`electron .` 开发启动时主进程 `defaultApp=true`，但 **preload renderer 拿不到该属性**；`start.js:86` 以 `electron .` 启动且不设置 `CUCKOO_DEBUG`（`start.js:78` 仅读 `CUCKOO_DEBUG_PORT`），因此 dev 路径判定落入静默分支。
- `process` 可用性：探针 `hasProcess: true`；本视图 `sandbox:false`（`app/entry.ts:203`），preload 拥有完整 Node `process`，`process.env` 可读。
- 边界取值（`console-filter.ts:25-26`）：`flag === '1' || flag === 'true'`；空串、`'0'`、`'TRUE'`、`'yes'` 均判为静默。`'0'` / 空串静默符合预期；大小写敏感与未覆盖其他真值见 F3。

## 3. 缺陷与风险取证清单

### [🟡 中（高优先）] F1：开发模式判定信号 `process.defaultApp` 在 preload 渲染进程不存在，dev 路径误静默

- **定位**：`src/bridge/console-filter.ts:19-27`；调用方 `src/bridge/console-filter-install.ts:7`；失实文档 `docs/requirements/130-preload-console-noise.md:47`、`CHANGELOG.md:22`、`changelogs/2026-11.md:10`、`.agents/handoff.md`（0C 节）。
- **事实证据**：
  - 取证命令：本地探针 `node_modules/electron/dist/electron.exe .agents/tmp-build-a/probe`（`sandbox:false, contextIsolation:true`），结果文件 `.agents/tmp-build-a/probe-result.json`：
    - 主进程：`mainDefaultApp: "true"`，`mainDefaultAppType: "boolean"`；
    - preload renderer：`defaultApp.type = "undefined"`，`defaultApp.own = false`（`Object.prototype.hasOwnProperty.call(process,'defaultApp') === false`），`type: "renderer"`。
  - 官方文档（https://www.electronjs.org/docs/latest/api/process ）：`process.defaultApp` 为 true **仅在主进程**，否则 `undefined`；沙箱 renderer 子集清单不含该属性。
  - `start.js:86` 以 `electron .` 启动，全程未设置 `CUCKOO_DEBUG`（`start.js:78` 仅处理 `CUCKOO_DEBUG_PORT`）；`src/app/entry.ts:209-211` 的 `additionalArguments` 也未携带开发态标记。
  - 推演：dev 启动 → preload 中 `defaultApp === true` 为 false、`flag` 为 undefined → `isDebugConsoleEnabled()` 返回 false → 过滤器安装 → preload 的 `log/info/debug` 被静默，与代码注释 `console-filter.ts:11`"开发启动…保持全部日志，避免调试失明"及文档承诺相反。
- **潜在危害**：
  1. 开发者在 `npm run dev` 下看不到 preload 侧诊断日志（拦截器 / 看门狗 / 重试 / 子代理 / 插件链路），排障失明；
  2. 主进程 `console-message` 转发器（`app/entry.ts:601-615`）在 dev 下同时收不到这些 preload 日志，`wyp/log/*.log` 平台日志文件随之缺段；
  3. 生产行为不受影响（打包版本就应静默）；无崩溃、无功能断链、无安全回退。
- **修复方案**（任选其一，推荐 A）：
  - A. 主进程在创建视图前把开发态显式传入渲染进程：`src/app/entry.ts:209-211` 的 `additionalArguments` 增加 `--cuckoo-debug=` + `(!app.isPackaged ? '1' : '0')`，preload 解析 `process.argv` 判定；判定逻辑不再依赖 renderer 的 `process.defaultApp`。
  - B. 主进程在 dev 下于窗口创建前设置 `process.env.CUCKOO_DEBUG = '1'`（renderer 环境变量继承已由探针证实可透传），preload 只读 env 分支。
  - C. 短期兜底：文档与注释先把"开发启动自动保留日志"改为"dev 需显式设置 `CUCKOO_DEBUG=1`"，避免承诺与行为不符。
- **信心评分**：9 / 10（本机 Electron 44.4.3 实测主/renderer 两侧取值；探针页面为 `data:text/html`，`process` 属性在 renderer 进程创建期注入、与页面 URL 无关；残留 1 分留给"真实 AI 页面 partition 下行为是否一致"的真机复核）。

- **事实证据**：
  - 取证命令：读测试文件，3 条用例中判定用例为 `isDebugConsoleEnabled({ CUCKOO_DEBUG: '1' }, false)` / `({ CUCKOO_DEBUG: 'true' }, false)` / `({}, true)` / `({}, false)`——`defaultApp` 全部由测试显式传参，**没有任何用例读取真实 `process.defaultApp`**；也无 Electron 集成探针断言 dev 下 preload 日志保留。
  - 因此 F1 这类"环境信号在 renderer 不存在"的假设错误，在单测层面不可见。
- **潜在危害**：判定来源再次换用错误信号（如 renderer 不可见的主进程 API）时，测试仍全绿，缺陷继续流入发布。
- **修复方案**：把信号读取与判定拆开（`isDebugConsoleEnabled(env, defaultApp)` 保持纯函数测试；另增一个读 `process.argv` / env 的薄封装做集成探针）；补充一条 Electron 探针或真机清单：dev 启动不设 env 时 preload `PRELOAD_*_LOG` 仍出现。
- **信心评分**：8 / 10。

### [🟢 轻] F3：`CUCKOO_DEBUG` 取值分支大小写敏感、真值集合过窄

- **定位**：`src/bridge/console-filter.ts:25-26`。
- **事实证据**：分支仅 `flag === '1' || flag === 'true'`；`'TRUE'`、`'True'`、`'yes'`、`'on'`、空串、`'0'` 均落入静默。`'0'` / 空串静默符合预期；大写与其他常见真值会被误判为生产。
- **潜在危害**：开发者按直觉设 `CUCKOO_DEBUG=True` 仍被静默，调试失明，且无报错提示。
- **修复方案**：归一化 `const flag = (env.CUCKOO_DEBUG || '').toLowerCase(); return defaultApp === true || flag === '1' || flag === 'true' || flag === 'yes' || flag === 'on';`；或在文档中明确仅接受小写 `1`/`true`。
- **信心评分**：7 / 10。

### [🟢 轻] F4：赋值中途抛错会留下半安装状态，catch 静默吞掉且返回值未被使用

- **定位**：`src/bridge/console-filter.ts:40-48`；调用方 `src/bridge/console-filter-install.ts:7`（未接收返回值）。
- **事实证据**：探针实测当前环境 `console.log/info/debug` 均 `writable: true, configurable: true`，赋值一次成功；若未来运行环境把 console 方法改为只读 / getter-only，严格模式下第二次赋值抛 `TypeError`，此时 `log` 已被替换、`info/debug` 仍是原生，过滤器处于半静默状态；`catch` 静默返回 `false`，安装方不检查返回值，无告警。
- **潜在危害**：异常环境下日志行为半残且无迹可查；当前 Chromium/Electron 环境不触发。
- **修复方案**：逐项 try 或先校验描述符，失败时回滚已替换项；catch 中用未被静默的 `console.warn` 记录一次安装失败。
- **信心评分**：6 / 10。

### [🟢 轻] F5：工具窗口 preload 的 `console.log` 不在本次覆盖范围（范围缺口记录）
