## 3. 缺陷与风险取证清单

### [🔴 严重] 硬件预设 deviceMemory 超出浏览器真实上限
- 定位：src/app/fingerprint.ts:46,59,68,79,90,101（预设池）、163-165（normalize 未夹上限）
- 事实证据：navigator.deviceMemory 规范仅返回 0.25/0.5/1/2/4/8（GiB），硬上限 8。预设 6 套中 4 套给 16、1 套 32，均为真实 Chrome 永不上报值；normalize 只判 >0。
- 潜在危害：伪装值与真实能力矛盾，反成强特征，风控判异常。
- 修复方案：预设收敛 ≤8；normalize 加 Math.min(8, ...) 夹紧。
- 信心评分：9/10

### [🔴 严重] 被替换的原生方法与 getter 带自有 prototype，一行可识破
- 定位：fingerprint.ts:240-249(markNative)、265(getter)、304/369/379/390/406(fake*)；net-identity.ts:387-391(Fake 构造)
- 事实证据：原生内置方法与访问器无自有 prototype。此处全为 function 表达式，自有 prototype 为 true。探针 Object.prototype.hasOwnProperty.call(HTMLCanvasElement.prototype.toDataURL,'prototype') 原生 false、此处 true；getter 同理。
- 潜在危害：整套 Native Cloaking 被单一探针击穿，toString 伪装无效。
- 修复方案：markNative 内 delete fn.prototype 并校准 length；getter 同样删；或改箭头函数后补 name。
- 信心评分：9/10

### [🟡 中等] 注入标记是可枚举自有属性且名字带 cuckoo
- 定位：fingerprint.ts:231-232（__cuckooFpInjected）；net-identity.ts:480-481（__cuckooShieldInjected）
- 事实证据：直接赋值 = enumerable 自有属性，Reflect.ownKeys/Object.keys(window) 可枚举，名字暴露工具身份。与 infra/user-agent.ts 注释「幂等标记必须放闭包内，挂 window 等于给页面留标签」矛盾。
- 潜在危害：页面一键判定"已被 Cuckoo 改装"，反指纹自曝。
- 修复方案：改闭包私有变量；确需跨 evaluate 幂等则用不可枚举 Symbol。
- 信心评分：8/10

### [🟡 中等] Canvas 噪点位运算 & 255 造成 0↔255 翻转
- 定位：fingerprint.ts:360-362
- 事实证据：(0 + -1) & 255 === 255，(255 + 1) & 255 === 0。位掩码在赋值 Uint8ClampedArray 之前回绕，clamp 失效。
- 潜在危害：边界像素椒盐跳变，统计特征异常，与「自然微扰」注释不符。
- 修复方案：改 Math.max(0, Math.min(255, d[i]+delta))。
- 信心评分：9/10

### [🟡 中等] 代理 setProxy 失败/超时被静默吞掉，存在直连真实 IP 窄窗口
- 定位：net-identity.ts:187-189（catch 仅 log 后返回）；entry.ts:667-674（.then 仍 safeLoadPage）
- 事实证据：applySessionProxy catch 吞异常不抛；启动时 setProxy 抛错或 5s 超时，session 保持 direct，随后 loadPage 直连真实 IP 且不触发 did-fail-load。注：常见「代理不可达」会走 did-fail-load 显示 proxy-error.html（不泄露）；本缺陷仅在 setProxy 本身失败/超时触发，场景窄但属 fail-open。
- 潜在危害：小概率静默泄露真实 IP，与需求108 目标相悖。
- 修复方案：失败/超时向上抛或返回状态；代理未生效时不加载真实站点，改加载 proxy-error.html；可加 ses.resolveProxy 验证。
- 信心评分：7/10

### [🟡 中等] 8s 外部兜底早于内部最坏预算，首帧可能无盾加载
- 定位：entry.ts:663-666（8s 强制 loadPage）；net-identity.ts:568-645（串行 withTimeout，最坏≈26s）
- 事实证据：setProxy 5s + 多个 3s 串行，慢机可超 8s；8s 定时器到点 loadPage 时 addScript 可能尚未执行，首帧文档无 WebRTC/DNS 盾。
- 潜在危害：首次导航无隐私盾，泄露防护首帧失效。
- 修复方案：盾脚本注入提前到 Emulation 之前；或兜底加载错误页；或兜底阈值 ≥ 内部最坏预算。
- 信心评分：7/10

### [🟡 中等] WebRTC 包装后 pc.constructor 可识破
- 定位：net-identity.ts:387-391, 467
- 事实证据：Fake 返回 new Native 实例，实例 constructor 沿原型链为 Native；window.RTCPeerConnection = Fake。new RTCPeerConnection().constructor === RTCPeerConnection 得 false（真 Chrome true）。
- 潜在危害：WebRTC 伪装可被识别。
- 修复方案：浅拷贝原型后 Fake.prototype.constructor = Fake（避免污染 Native）；或对返回实例 defineProperty constructor。
- 信心评分：7/10

### [🟡 中等] WebGL 画布 readPixels 未拦截，指纹裸奔
- 定位：fingerprint.ts:332-367（applyCanvasNoise 仅 2D）
- 事实证据：WebGL canvas getContext('2d') 返回 null 直接 return；readPixels 完全未包装。Three.js 等主流 WebGL 指纹零防护。
- 潜在危害：反指纹在 WebGL 路径失效。
- 修复方案：对 readPixels 做确定性微扰，或文档标注已知边界。
- 信心评分：7/10

### [🟡 中等] devtools-closed 重挂未 normalize 代理配置
- 定位：entry.ts:797（对比 711 已 normalize）
- 事实证据：devtools-closed 直接取原始对象，缺 webrtc 字段时 needShield 可能 false → 关 DevTools 后盾未真正重挂。
- 潜在危害：与日志「已自动重新挂载」不符，形成泄露窗口。
- 修复方案：与 711 行统一 normalizeProxyConfig。
- 信心评分：6/10

### [🟡 中等] 测试深 mock，违反项目 test 规则且掩盖真实缺陷

- 修复方案：改真实语义集成测试，补失败路径。
- 信心评分：8/10
