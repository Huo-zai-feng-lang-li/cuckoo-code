## 3. 缺陷与风险取证清单

### [🔴 严重] `.ck-skill-item` 选择器被误删，列表基础布局样式失效
- **定位**：`src/ui/shell/styles/components.css:309-313`（生成物 `src/ui/shell.html:667-671`、`:812` 同）
- **事实证据**：
  - Diff 末尾：`-  .ck-skill-item {` 这一行被删除，其后 `display: flex; flex-direction: column; gap: 6px; ...` 变成裸露声明，第 313 行残留孤立的 `}`。
  - `grep "ck-skill-item"` 核实：`.ck-skill-item` 的 display/flex-direction/padding/cursor 基础规则已不存在，仅剩 `+.ck-skill-item` 与 `:hover` 两条残留规则引用它。
  - `src/ui/shell.html:667` 与 `:812` 同样出现裸露声明（生成物已同步出错）。
- **潜在危害**：技能列表、子代理列表、规则列表全部退化为默认 div 布局——desc 不再换行、无内边距、hover 圆角/分隔线视觉错乱；CSS 解析器跳过孤立块，若后续被压缩器重排还可能吞掉相邻规则。
- **修复方案**：在 `components.css:309` 前补回 `.ck-skill-item {`，并删除第 313 行多余 `}`；重跑 `npm run compile` 重建 shell.html。
- **信心评分**：10 / 10

### [🟡 中等] 宠物缓存 Map 无淘汰，反复换图内存无界增长
- **定位**：`src/app/ipc/harness.ts:476-478`（`const petCache = new Map<string, string>()`）
- **事实证据**：cache key 为 `路径_mtimeMs`，每次图片修改都产生新 key 且从不删除；`grep "petCache" ` 确认无 `delete`/`clear`/容量上限。
- **潜在危害**：用户反复调整自定义图片（每次 mtime 变化）会持续累积 base64 缩略图（约 30-60KB/张），长期运行主进程内存单调上升。
- **修复方案**：加 LRU 或简单上限（如 > 50 条时清空重建），或按路径维度只保留最新一张。
- **信心评分**：8 / 10

### [🟡 中等] 设置页文案「绝不会拉伸变形」与实现不符
- **定位**：`src/ui/shell/partials/pages/settings.html:56`（文案）vs `src/app/ipc/harness.ts:463`（`img.resize({width:128,height:128})`）
- **事实证据**：`nativeImage.resize` 同时指定宽高会直接拉伸到 128×128，不做等比裁切；文案承诺「居中等比裁切，绝对不会被拉伸变形」属**注释/文案撒谎**。最终 CSS `background-size: cover` 只对已拉伸后的 1:1 图做圆形裁切，非正方形原图视觉上已变形。
- **潜在危害**：用户按文案预期放置 16:9 图，看到宠物被压扁/拉长，属可见体验缺陷与信任损耗。
- **修复方案**：二选一——(a) 实现等比裁切后再 resize（先算短边裁正方形）；(b) 修正文案，如实说明会被拉伸填充。
- **信心评分**：8 / 10

### [🟡 中等] 宠物列表去重只比对首项，部分换图不刷新
- **定位**：`src/ui/shell/scripts/pages/agents.ts:19`（`if (petImages.length === files.length && petImages[0] === files[0]) return;`）；`src/ui/harness.html:1240` 同逻辑
- **事实证据**：仅比较数组长度与第 0 项 base64。用户在文件夹中只替换第 2 张及以后的图片时，长度不变、首项不变 → 判定"未变化"直接 return，轮换列表不更新。
- **潜在危害**：用户换了图但界面仍显示旧图，误以为功能失效。
- **修复方案**：比较完整数组（`files.join('|') === petImages.join('|')`，或长度+首尾+中间抽样）。
- **信心评分**：6 / 10

### [🟡 中等] 目录遍历逐文件同步 statSync，阻塞主进程
- **定位**：`src/app/ipc/harness.ts:487-505`（`addFileOrDir`）
- **事实证据**：`readdirSync` 后对每个文件调用两次 `fs.statSync`（size + mtimeMs），且全部同步执行于 `ipcMain.handle` 内。`window focus` 会触发 `refreshPetsAll` → `listPets`，频繁焦点切换时重复同步扫描。
- **潜在危害**：自定义宠物目录含大量图片时，主进程被同步 IO 阻塞，UI/IPC 卡顿。
- **修复方案**：改用 `fs.promises` 异步；或一次性 `readdirSync({withFileTypes:true})` + 单次 `stat`，并对 focus 刷新做节流。
- **信心评分**：7 / 10
