# 全项目全功能输入到输出深度审计与Bug修复计划

## 1. 目标
对 `cuckoo-code` 进行全功能、全链路的端到端深度审计，排查各层输入验证、状态流转、并发安全、异常处理及桌面集成缺陷，确保代码专业、无 Bug、性能卓越，并直接修复定位到的所有 Bug。

## 2. 审计与修复模块矩阵

### 阶段一：桌面与窗口系统集成
- [ ] **任务栏图标与窗口图标不一致修复**：
  - 根因排查：Windows 平台开发环境下 `setAppUserModelId` 与 `electron.exe` 的行为差异；`BrowserWindow` 的 `icon` 参数直接传递绝对路径以确保原生渲染保真度。
  - 覆盖所有窗口：OAuth 弹窗、飞书设置教程窗口、Subagent 窗口、独立打开窗口等，确保统一配置应用图标。

### 阶段二：主进程核心 IPC 与输入/输出链路防御
- [ ] **`src/app/ipc/shell.ts` 协议校验**：
  - 外部链接与导航地址的 URL 协议严格校验，防御伪协议注入。
- [ ] **`src/rules/files.ts` 文件操作防御**：
  - 路径严格安全校验（防路径穿越），文件名合法性校验（禁止系统非法字符与空名），原子写入与错误捕获。
- [ ] **`src/session/store.ts` 工作区与会话数据防腐**：
  - 会话数据持久化校验，避免非法 ID 导致数据落盘失败或内存与磁盘状态分叉。

### 阶段三：Bridge 自动化注入与 Provider 交互闭环
- [ ] **`src/overlay/chat-input.ts` 发送链路锁与状态互斥**：
  - 发送链路防并发竞争，确保消息发送流水线的互斥与有序。
  - ContentEditable 与多行文本回车换行逻辑的边界处理。
- [ ] **Providers 鲁棒性校验**：
  - 检查 ChatGPT、Claude 等各 Provider 的 DOM 元素定位与可见性检查，杜绝任何 `undefined` 属性访问。

### 阶段四：工具执行层（Tool Execution）安全与资源泄露防御
- [ ] **子进程管理（`bash.ts` / `pwsh.ts`）**：
  - 超时杀死进程组时的 Windows 树形杀进程机制（`taskkill /F /T /PID` 兜底），防止后台孤儿进程泄露。
- [ ] **文件系统工具（`read.ts` / `edit.ts` / `write.ts`）**：
  - 空输入、非 UTF-8 二进制大文件、超长行边界防护。

### 阶段五：构建编译与自动化测试回归
- [ ] 运行全量 TypeScript 严格类型检查。
- [ ] 运行全量 Vitest 单元测试套件，补全新增功能的单测。
- [ ] 执行全套编译构建步骤验证。
- [ ] 最终更新 handoff 文档与审计结论。
