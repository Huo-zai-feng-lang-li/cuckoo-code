## 3. 缺陷与风险取证清单

### [🟡 中等] 新对话函数缺少「同 URL 导航」短路，选目录后可能不初始化项目且遮罩滞留
- **定位**：`src/app/ipc/session.ts:442-486`（`startNewConversationForProject`）
- **事实证据**：
  - 对照 `src/app/ipc/shell.ts:245-247` 明确注释：「若目标与当前相同（用户已在首页点「+」），Electron 可能不派发 did-finish-load → onLoad 不执行 → 遮罩残留到 15s 兜底」，并在 `:278` 用 `else if (beforeUrl === url && onLoad) setTimeout(onLoad, 100)` 兜底。
  - `startNewConversationForProject` **没有**该短路逻辑：`loadURL(homeUrl)` 后若未触发 `did-finish-load`，`onLoad` 不执行 → `initProject` 不被调用 → 项目未绑定、系统提示词未注入；`notifyDone` 也不执行 → loading 遮罩滞留至 15s 兜底。
  - 该函数原为 `new-conversation-for-project` 的内联体（缺陷既有），本次被提取并**新接入**「左上角项目选择器」与「Ctrl+Shift+N」两条主路径，暴露面扩大。
- **潜在危害**：用户在首页点项目选择器/Ctrl+Shift+N 选目录 → 界面回到首页看似成功，但项目未绑定，后续工具拿不到 projectDir；遮罩卡 15s，体验为「点了没反应」。
- **修复方案**：进入 `loadURL` 前记录 `beforeUrl = wc.getURL()`，`loadURL` 后补 `else if (beforeUrl === homeUrl && onLoad) setTimeout(onLoad, 100)`（照抄 shell.ts 的做法）。
- **信心评分**：7 / 10（缺陷存在确凿；触发为间歇性，取决于 Electron 是否派发 did-finish-load）

### [🟢 轻微] 新 IPC 未做来源校验（防御纵深）
- **定位**：`src/app/ipc/session.ts:488-512`
- **事实证据**：相邻的 `write-project-file`/`create-project-entry` 等均有 `assertSenderOk(event)`（`:129/:164/:185/:209`），而 `new-conversation-for-project` 与 `pick-dir-and-new-conversation` 没有。二者仅由 `shellAPI`（壳页面 file://）暴露，AI 页面 `electronAPI` 不含该通道。
- **潜在危害**：需壳页面先被 XSS 才可利用，非直接可利用；属 X-001「副作用面硬来源校验」未对齐。
- **修复方案**：两处 handler 开头加 `if (!assertSenderOk(event).ok) return { success:false, error:'来源校验失败' };`。
- **信心评分**：6 / 10（系统性既有模式，非本次回归）
