- 证据：

  - `src/app/ipc/project.ts:72,203`、`src/tools/impl/run-agent.ts:110,171`：同样无信任门。
  - `src/infra/workspace-trust.ts:134-184` `scanWorkspaceArtifacts` 只探测 `.agents/{mcp.json,rules,skills}`，**不探测 `.cuckoo/agents/`** → 恶意仓库的子代理文件**不会触发信任弹窗**（`workspace-trust-prompt.ts:66-67` 判 hasArtifacts=false → 直接 trusted:true）。
- 影响：克隆恶意仓库后，仓库可带 `.cuckoo/agents/evil.md`（frontmatter `tools: bash` + 攻击者 systemPrompt）。信任门不弹；其 name/description 注入主系统提示词，AI 一旦 `runAgent('evil',…)` 即以攻击者 systemPrompt + bash 工具启动子会话。这正是 D-004"项目文件注入提示词 / 授予代码执行"的威胁模型，只是被漏在了第四类内容（子代理）上。命令仍走 X-001 host 闸，故非直接 RCE，但"打开恶意项目前先信任"的承诺对子代理不成立。
- 建议修法：
  1. `scanWorkspaceArtifacts` 增扫 `.cuckoo/agents/*.md`（使信任弹窗可见）；
  2. `scanAgents` 对 `source==='project'` 在 `!isWorkspaceTrusted(projectDir)` 时不返回（对齐 rules/skills 数据层兜底），并在 prompt-builder/project.ts 的 agents 调用补 `filterProjectScoped`。
