# 114：发送延迟分布改造与默认值统一

> 状态：**done**
> 分支：`feat/114-send-delay-distribution`

## 用户目标与约束

1. 工具循环等待感明显降低（当前每轮 30~36 秒，20 轮就要 10 分钟起步）。
2. 不得因此增加封号风险。
3. 修掉默认值三处不一致的历史遗留。

## 现状核查

### 体感慢的真实成因

`src/overlay/chat-input.ts:37`：

```ts
const ratio = Math.min(1, len / 4000);
const cognitiveBase = min + ratio * (max - min);
```

Cuckoo 的典型场景是工具循环，每轮回传的观察结果动辄几千到上万字符，**`ratio` 恒等于 1** → 延迟永远贴在配置上限（默认 36 秒）。20 轮工具循环 = 10 分钟以上纯等待。

同时短消息（<100 字符）也受制于 `min`=12 秒，无法快速响应。

### 默认值三处不一致（历史 bug）

| 位置 | 默认 min | 说明 |
|---|---|---|
| `global-settings.ts:64` | 12 秒 | 主进程唯一真相源 |
| `overlay/state.ts:22` | 12000 毫秒 | 与主进程一致 |
| `overlay/panels/settings.ts:56,196,310` | **6 秒** | 设置面板的「恢复默认」，与主进程矛盾 |

点「恢复默认」写 6 秒 → 主进程下一次广播又冲回 12 秒。0.10.215 只修了保存链路，没修默认值本身。

### 关于「设短会封号」的评估

真正触发风控的信号是：请求间隔恒定且机械、长时间不间断高频、服务端真限流（已有 120 秒 429 退避兜底）。

**12 秒这个值缺乏依据**，且「恒定慢」本身就是一种非人类特征（真人分布是"多数快、偶尔很慢、有长尾"，不是匀速慢）。

## 方案

### 1. 分布形状：线性 → 平方根压缩

```ts
// 旧：len=4000 就到顶（工具结果几乎必到顶）
const ratio = Math.min(1, len / 4000);

// 新：len=16000 才到顶，且用 sqrt 压缩前段
const ratio = Math.min(1, Math.sqrt(len / 16000));
```

效果（默认 4~30 秒）：

| 内容长度 | 旧延迟 | 新延迟 |
|---|---|---|
| 20 字符 | 12~18s | 4~6s |
| 500 字符 | 12~18s | 6~9s |
| 2000 字符 | 19~29s | 10~15s |
| 8000 字符 | 30~36s | 20~28s |
| 20000 字符 | 30~36s | 26~30s |

**总等待时长减少约 60%，且分布更分散（更像人）。**

### 2. 抖动幅度：±20% → ±35%

恒定节拍是比「慢」更危险的机器特征。加大抖动让每次间隔差异更明显。

### 3. 默认值统一为 4~30 秒

三处（主进程 / state / 设置面板）全部对齐到 4~30。

### 4. 迁移链：兼容两代旧默认

`LEGACY_DEFAULTS` 从单值改为数组，依次匹配：
- 一代：1/10 秒（旧版毫秒默认 1000/10000）
- 二代：12/36 秒（0.10.216~217 的防封默认）
- 当前：4/30 秒

用户真实自定义的值（偏离所有旧默认）原样保留。

## 风险与防御

- **不改 429 退避**（120 秒）——服务端限流信号才是硬约束，这个兜底不动。
- **不改重试间隔**（15~30 秒）——失败重连与正常发送是两回事。
- **短消息快速通道**：len < 200 时 ratio ≈ 0，延迟贴近 min（4~6s），体感明显改善。
- **保留 max 上限**：超长内容（20000+ 字符）仍会逼近 30 秒，不无限加速。

## 验收标准

- [x] 默认值三处一致（4/30 秒）
- [x] 短消息（20 字符）延迟 ≤ 8 秒（单测 `randomDelay: 短内容走快速通道` 锁死 ≤ 8s）
- [x] 长消息（8000 字符）延迟 ≤ 28 秒（sqrt 压缩后 8000 字 ratio≈0.707）
- [x] 分布分散度提升（同长度多次调用取值数增加，抖动 ±20% → ±35%）
- [x] 两代旧默认均能迁移到 4/30（`LEGACY_SEND_DELAY_RANGES` 数组 + 两条回归用例）
- [x] typecheck / test(135 文件 1399 用例) / lint(0 errors) / compile 全绿
- [ ] 真机验证延迟分布（体感项，数学行为已由单测覆盖，实际等待感受待用户确认）

## 实施记录（与原方案的偏差）

### 1. 命中下限的抖动幅度改用 min 自身比例

原方案只写了「抖动 ±20% → ±35%」，未处理边界抖动。实现时发现既有代码：

```ts
const span = (max - min) * 0.25;
if (clamped === min) return Math.round(min + Math.random() * span);
```

默认区间改成 4~30 后跨度 26 秒，25% 就是 6.5 秒 —— 短消息命中 min 后会被抖到 4~10.5 秒，
与「短消息快速响应」的目标直接冲突（旧 12~36 区间跨度 24s，25% 也有 6s，同样偏大，
只是旧下限本来就是 12s，不那么明显）。

改为拆分两个 span：
- `spanLow = Math.min((max - min) * 0.25, min * 0.6)` —— 默认 4s 时跨度降到 2.4s（4~6.4s）
- `spanHigh = (max - min) * 0.25` —— 上限侧不变（长文本仍慢，不反转到最快）

### 2. 迁移链从单值改为数组

原方案写「LEGACY_DEFAULTS 从单值改为数组」，实现时进一步把 sendDelay 单独提出来
（`LEGACY_SEND_DELAY_RANGES`）：它的历史默认有两代，而其它字段（retryDelay 等）只有一代，
混在一个对象里会让「一对多」的语义变模糊。

## 遗留 / 后续
